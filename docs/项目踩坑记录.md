# 项目踩坑记录

## [2026-08-13] Windows 沙箱内 Maven 编译 AccessDeniedException

- 现象：javac 读取 `spring-aop-6.1.14.jar` 后关闭 zipfs 时报 `java.nio.file.AccessDeniedException`，与 jar 是否损坏无关（`jar tf` 可正常读取）。
- 位置：`jdk.nio.zipfs.ZipFileSystemProvider.removeFileSystem -> path.toRealPath`。
- 解决：Maven 使用 `-Dmaven.compiler.fork=true` 并在 `pom.xml` 的 `maven-compiler-plugin` 中配置 `<fork>true</fork>`；在沙箱外运行 Maven 完成测试。
- 补充：本机全局 Maven `settings.xml` 的 localRepository 指向不可写目录，通过项目内 `.mvn/user-settings.xml` 覆盖。

## [2026-08-13] 测试时间戳硬编码

- 问题：测试中硬编码 `Instant.parse("2026-08-13T00:00:00Z")` 对应毫秒数，与实际值不一致，2 个断言失败。
- 解决：改为从 `metadataStore` 读取 `updatedAt.toEpochMilli()` 动态断言。

## [2026-08-13] OfficeCLI 集成方案判断

- 需求优先考虑 OfficeCLI 中间层，但阅读官方 README 后确认其为本地 CLI，无编辑配置 REST API 与 Document Server 转换封装。
- 决定直接集成 OnlyOffice Document Server 官方 API，并在 README 中说明原因。

## [2026-08-13] 对接已有 OnlyOffice 容器

- 已用 `docker run` 启动的 OnlyOffice 容器默认在默认 bridge 网络，直接跑根目录 `docker-compose.yml` 会重复创建同名容器并冲突 8080 端口。
- 推荐先 `docker network create office-net`，再把已有 `onlyoffice-document-server` 容器 `docker network connect` 进去，然后用 `docker-compose.app.yml` 只启动 App。
- 原版 `onlyoffice/documentserver` 镜像没有 `fonts-noto-cjk`，PDF 转中文会乱码；需 `docker exec -u root` 安装字体后重启容器。

## [2026-08-13] Linux 解压 tar 报权限错误

- 问题：`/app` 目录由 root 创建，普通用户 `gitzhou` 解压时报 `mkdir: 权限不够`；之前失败的解压残留还会导致 `src/main` 等目录状态混乱。
- 解决：`sudo rm -rf /app/office-online` 清理后，用 `sudo mkdir -p` 和 `sudo tar -xzf ... -C ...` 解压，再 `sudo chown -R $USER:$USER` 把目录交给当前用户。

## [2026-08-13] Docker 构建卡在 Maven 下载依赖

- 问题：Dockerfile 的 `mvn dependency:go-offline` 默认访问 Maven Central，国内网络很慢，且 `-q` 不显示进度，看起来像卡死。
- 解决：新增 `docker/maven-settings.xml` 使用阿里云镜像，Dockerfile 中 `COPY` 到 `/root/.m2/settings.xml`，并去掉 `-q` 改为 `-B` 显示下载进度。

## [2026-08-13] 前端 SDK 加载失败与转换响应解析失败

- 问题：`ONLYOFFICE_URL` 设为容器名后后端正常，但浏览器无法解析 `onlyoffice-document-server`，导致前端 SDK 加载失败。
- 解决：新增 `ONLYOFFICE_PUBLIC_URL` 给前端使用，后端仍用 `ONLYOFFICE_URL` 做容器间调用。
- 问题：转换接口可能返回 gzip 或非 JSON 内容，导致 `Failed to parse OnlyOffice conversion response`。
- 解决：OnlyOffice 请求增加 `Accept-Encoding: identity`，并把原始响应写入异常消息，便于定位。

## [2026-08-13] OnlyOffice JWT 令牌报错

- 问题：打开预览/编辑时报“文档安全令牌的格式不正确”，原因是 Document Server 开启了 JWT，App 未配置相同 `ONLYOFFICE_JWT_SECRET`。
- 排查：`docker exec onlyoffice-document-server env | grep JWT` 查看 OnlyOffice 容器实际使用的 `JWT_SECRET`。
- 解决：把该密钥写入 `/app/office-online/.env` 的 `ONLYOFFICE_JWT_SECRET`，再 `bash deploy.sh` 重建 App 容器。
- 补充：`env | grep JWT` 无输出不代表 JWT 未开启，密钥可能写在 `/etc/onlyoffice/documentserver/local.json`；找不到时先试默认值 `secret`。
- 备选：若不需要令牌，可在 OnlyOffice 容器加 `-e JWT_ENABLED=false` 关闭，并清空 App 的 `ONLYOFFICE_JWT_SECRET`。
- 补充：`local.json` 中 `token.inbox.inBody=false` 时，OnlyOffice 要求令牌放在 `Authorization` 请求头；App 已改为 header 方式传令牌。

## [2026-08-13] OnlyOffice 转换接口返回 XML

- 问题：`ConvertService.ashx` 可能返回 XML `<FileResult>`，旧代码只解析 JSON，导致报 `Failed to parse OnlyOffice conversion response`。
- 解决：转换解析兼容 JSON 与 XML，从 XML 的 `FileUrl`、`EndConvert` 节点提取结果。

## [2026-08-13] 下载链接出现容器名 office-online-app

- 问题：`APP_PUBLIC_URL` 使用了 Docker 容器名，浏览器无法访问，PDF 下载链接变成 `http://office-online-app:8081/...`。
- 解决：把 `APP_PUBLIC_URL` 设置为浏览器可访问的 `http://服务器IP:8081`，重建 App 容器。
